# Contributing Through GitHub Issues

All the repositories developed for CMSE 802 are Open Educational Resources (OERs). One way we give back to the open-source community is by reporting problems and suggesting improvements.

You do not need to know how to fix a problem to make a valuable contribution.

## When Should I Open an Issue?

Consider opening an issue when you find:

- a bug
- incorrect code
- missing files
- confusing instructions
- documentation errors
- suggestions for improvement

Issues are primarily for tracking problems and improvements.

If you have a question about:

- grades
- due dates
- course policies
- assignment expectations

please ask the instructor directly.

A useful rule of thumb is:

> If the answer only helps you, ask the instructor. If the answer would improve the repository for everyone, open an issue.

## Writing a Good Issue

A good issue includes:

- What happened?
- What did you expect?
- How can someone reproduce the problem?
- Any relevant error messages
- Information about your system if relevant

Example title:

> Part 2 notebook fails when generating synthetic data
> 
> Example description:
> 
> Expected: The notebook should generate a plot.
> 
> Observed: Running Cell 7 produces a ModuleNotFoundError.
> 
> Steps to Reproduce:
> 
> 1. Clone repository
> 2. Create environment using provided environment.yml file
> 3. Open notebook
> 4. Run all cells


## Pull Requests

Issues identify problems.

Pull requests propose solutions.

Typical workflow:

> Issue --> Develop Fix --> Submit Pull Request --> Review --> Merge

Students who are comfortable with Git are welcome to submit pull requests.

When possible, create an issue first and reference it in the pull request:

> Fixes #17

or

> Closes #17

This helps maintainers understand what problem the pull request addresses.

## Why This Matters

The course repositories are living resources that improve over time.

Good citizens of the open-source community help identify problems, improve documentation, and suggest improvements.

Remember:

> You do not need to know how to fix a problem in order to report it.

Carefully describing a problem is often just as valuable as fixing it.
