# Repository Review and Cleanup - Day 2

## Agenda (80 minutes)

1. 5 min - Check-in and review plan
2. 35 min - Group peer review, two passes (about 15 min each, plus switch time)
3. 25 min - Fix your own repository using the feedback
4. 15 min - Share-out and commit-your-fixes checkpoint

### Learning Goals

By the end of this class, you should be able to:

- Run a teammate's project from a fresh clone and report what you observed.
- Turn peer feedback into concrete repository fixes.

## Group Peer Review

Work in groups of two or three. Each reviewer clones the teammate's repository into a new folder, follows only the README, and fills in the [Quick Peer Review Form](../Guide/21-Peer-Review-Quick-Form.md). The goal is reproducibility evidence, not grading, so record exactly which command failed and why.

Review focus:

- Can I set up and run the project from the README alone?
- Is the repository easy to read, with no clutter?
- Are reflections in `paper/` and the git history readable and following the course guidelines?
- Is there at least one test or check I can run? (Milestone 3 is due Sunday.)

Projects using restricted data should provide a synthetic or example workflow for review.

## Fix Your Own Repository

Use the feedback you received to make at least three fixes, each as a small commit. Prioritize anything that blocked your reviewer from running your project. Leave a short note in your README or `paper/` folder describing what you changed and why.

## Before Next Class

- Finish remaining fixes and push them.
- Keep working toward the Milestone 3 testing and validation baseline.
