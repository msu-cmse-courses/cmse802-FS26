# Final Project Code Review - Day 3

This is the final in-class review before final project submission and presentations. Use the review to confirm that another researcher can understand the project, run its central workflow, evaluate its evidence, and see what remains outside the current scope.

## Agenda (80 minutes)

1. 5 min - Check-in and final-review plan
2. 10 min - Share post-holiday progress and remaining final-project risks
3. 35 min - Group peer review, two passes (about 15 min each, plus switch time)
4. 20 min - Fix your own repository using the feedback
5. 10 min - Share final results, handoff status, and presentation readiness

### Learning Goals

By the end of this class, you should be able to:

- evaluate a teammate's final project from the perspective of a future research collaborator; and
- turn final review feedback into concrete handoff and presentation improvements.

## Group Peer Review

Work in groups of two or three. Each reviewer begins from a fresh clone, follows only the README, and completes the [Quick Peer Review Form](../Guide/21-Peer-Review-Quick-Form.md). Record observable evidence: commands run, results reproduced, tests checked, and any remaining blockers.

Review focus:

- Can I identify the project question, central workflow, expected result, and known limitations?
- Can I set up and run the project using the documented commands?
- Does the repository contain the evidence needed to assess Safe, Portable, Reproducible, Robust, and Literate practice?
- Is the project ready to hand off, including a shareable data path or synthetic/example workflow where needed?
- Is the final presentation consistent with what the repository can actually demonstrate?

## Fix Your Own Repository

Make at least three small, focused fixes or record a concrete plan for any issue that cannot be completed before submission. Commit the changes and update the README, handoff note, or presentation materials so they match the final project state.

## Before Next Class

- Push final review fixes and the completed review form.
- Complete the final project submission and presentation materials.
- Prepare to demonstrate the actual workflow and evidence represented in your repository.
